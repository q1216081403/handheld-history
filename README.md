# 掌机时光机：一本可以玩的游戏史

一个可以实际运行的中文互动网页应用。用户通过阅读短故事、操作虚拟掌机、体验小游戏、对比与完成任务，理解每款掌机的特点以及它在游戏史上的位置。

> **本仓库当前状态：第一阶段可运行纵向样例（v0.1）。**
> 6 个教学章节 +47 条图鉴资料，**不是完整课本**。页面页脚与来源页均明确标注这一点。

---

## 一、快速开始

```bash
cd handheld-history
npm install

# 开发模式（热更新）
npm run dev        # http://localhost:5173

# 类型检查 + 生产构建
npm run build

# 预览生产构建
npm run preview    # http://localhost:4173

# 仅做类型检查
npm run check
```

环境要求：Node.js 18+（实测 22.13）、现代浏览器（Chrome / Edge / Safari / Firefox）。

## 四、6 个教学章节与互动设计

每类设备的体验都依据其**已核实的硬件特性**设计，没有共用同一个小游戏。

| 设备 | 互动玩法 | 讲解的核心 |
| --- | --- | --- |
| Mattel Auto Race (1976) | 灯点赛道躲避 + 4 挡换挡 | 没有像素屏时如何用点表达游戏；为什么用换挡开关而非油门 |
| Game Boy (1989) | 拖拽虚拟卡带插入 + 同一段原创画面做灰度/彩色对比 + 屏幕与负载教学模型 | 可换卡带的意义；便携与续航的取舍 |
| Nintendo DS (2004) | 上屏显示结果 / 下屏触摸操作的顺序谜题 | 为什么拆成两块屏而不是做更大 |
| PSP (2004) | 16:9 宽屏场景 + 模拟块导航（键盘方向键） | 宽屏的机会与麻烦；滑块式输入与摇杆的差异 |
| Switch (2017) | 把掌机拖进底座切换三种形态 | 同一台机器上什么相同、什么被牺牲 |
| Steam Deck (2022) | 功耗/分辨率/帧率取舍实验 | 为什么续航总是"取决于游戏" |

另有**冷门机型热点互动**（外观热点标记 + 部件说明）与**卡片插入**类体验备选，供后续机型接入。

## 五、真实性与边界（重要）

本项目在实现层面严格遵守以下规则，测试用例对这些规则做了断言：

- **所有音乐与音效都是 Web Audio 实时合成**，不使用任何商业游戏 BGM、录音或音频文件。音效统一标注为教学音效。
- **所有小游戏画面、规则、声音均为原创**，不运行 ROM，不嵌入任何商业游戏资产。
- **所有外观图都是原创 SVG**，页面统一标注"外观示意· 原创绘制，非官方图片素材"。
- **每台设备有独立外观造型**：48 台设备各有专属造型（依据公开工业设计资料还原比例与按键布局），仅 4 条非设备的数据条目使用通用图形；不存在"所有掌机套同一外壳"。全部造型使用统一的扁平矢量质感（渐变机身 + 内凹屏幕 + 立体按键 + 柔和投影），还原依据与视觉规范见 `docs/appearance-notes.md`。
- **教学模型明确标注**：Game Boy 的续航模型、Steam Deck 的性能/功耗模型都在界面上写明"不是实测数据""不提供任何具体游戏的帧率"。
- **触觉反馈不虚构状态**：默认关闭；无振动接口时显示"仅视听模拟（此设备未提供可用振动接口）"；有接口时显示"真实振动可尝试（已发送请求，不等同于已确认硬件震动）"。
- **事实分层**：每条陈述都带`史实` / `教学简化` / `主观评价` 标记，并链接到具体来源。
- **不声称完整**：页脚与来源页只显示实际条目数量，列出已知遗漏与争议项。
- **未上市产品单列**：串流设备（Portal、G Cloud）明确标注"串流设备（不运行本地游戏）"，与可换卡带掌机区分。

## 六、无障碍与设备适配

- 手机（390px）、平板（820px）、桌面（1440px）均无横向溢出，已实测。
- 「减少动态效果」开关 + 系统 `prefers-reduced-motion` 双支持，同时禁用视觉位移与抖动。
- 「关闭屏幕闪烁」开关；本项目本身不使用闪烁动画。
- 「教学放大 / 原始低分辨率」切换与「像素网格」开关，复古效果不让文字变得难读。
- 触觉反馈有弱/中/强预设、频率限制（最小间隔 90ms）、独立测试按钮与立即停止按钮。
- 键盘可操作：Auto Race 与 PSP 体验支持方向键；所有可交互元素可聚焦。
- 无音频权限时不崩溃，显示可点击的"恢复播放"横幅。
- localStorage 被禁用（隐私模式 / 策略拦截）时降级为无进度模式，不影响阅读与互动。
- 所有图片资源加载失败时页面仍可用（外壳为内联 SVG，不依赖外部图片）。

## 七、测试

```bash
# 先启动预览服务器
npm run build && npm run preview

# 另开终端运行
pip3 install playwright && playwright install chromium
python3 tests/e2e.py
```

`tests/e2e.py` 覆盖 68 项断言，包含：五个页面的渲染、六类互不相同的互动流程（图鉴搜索的缩写/年份命中、对比表列数、印章发放、localStorage 持久化）、**外观专项（各章节「示意画面」文字必须落在屏幕内、章节机型外观比例互不相同）**、移动端与平板视口、键盘操作、存储被禁用、图片全部失败、系统减少动态偏好、无振动接口环境。

**真实运行结果：68/68 全部通过**（见 `tests/RESULTS.txt`）。测试过程中发现并修复了 4 个真实缺陷：

1. `ExpAutoRace` 的交通数据初始为空数组，导致渲染崩溃（React error #520）。
2. `saveProgress` / `resetProgress` 的 `typeof localStorage` 检查放在 `try` 之外——`typeof` 也会触发 getter，在存储被禁用时抛错导致整页白屏。
3. `haptics.setEnabled` 不广播状态变化，导致启用震动后界面文案仍显示"已关闭"。
4. 「示意画面」占位文字的坐标由 `SCREEN_LABEL_POS` 按设备 id 硬编码，外观一改就与屏幕错位。改为由造型函数自行声明屏幕矩形（`screen` 参数），`DeviceShell` 据此渲染文字，并删除该坐标表。

此外补充了一处健壮性改进：振动调用增加"用户手势"守卫，避免浏览器拒绝 `navigator.vibrate` 时产生控制台错误。
